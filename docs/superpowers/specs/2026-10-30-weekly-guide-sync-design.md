# 每周指南更新提案

用户已选择：每周自动检查，有变化时创建更新提案，人工合并；没有变化不创建提案。

## 方案

在 GitHub Actions 运行，每周一北京时间 09:17（UTC 01:17），同时允许手动触发。按需手动更新需要重复操作；直接自动合并缺少阅读差异的环节；因此采用每周创建或更新同一条 PR。

## 边界

- 上游固定为 `eternity4719/HowToLiveBetter` 的 `main`。
- 同步 `guides/how-to-live-better/` 完整 Git tree，不执行其中的代码。
- 只允许自动更改指南目录、`sync/how-to-live-better.json` 和 `UPSTREAM.md` 中的同步区块。
- 本地工作区有改动、指南被自行修改、元数据不一致、来源拉取失败时停止，不覆盖个人内容。
- 无内容变化不改日期、不产生提交。提案使用固定分支 `automation/update-how-to-live-better`，保留人工合并。
- 提案说明包括旧、新版本、上游对比链接和新增/修改/删除文件数量。
- 使用仓库短期 GITHUB_TOKEN，默认权限仍为只读；同步任务仅申请 contents 与 pull-requests 写权限。动作固定完整提交 SHA。
- GitHub 可能延迟任务；公开仓库 60 天无活动时定时任务可能被停用，说明中提供手动运行和恢复入口。

## 验收

真实 Git 仓库测试覆盖更新、无变化、重复运行、二进制/换行保真、个人笔记、手工修改指南、脏工作区、来源失败、损坏元数据与空来源。发布后实际触发一次工作流，核对执行结果、目录边界和提案状态。
